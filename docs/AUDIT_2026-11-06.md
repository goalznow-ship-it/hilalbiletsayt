Bakı vaxtı brauzerin saat qurşağından asılı deyil. Qaralama, arxiv, keçmiş, bağlı və dolu sessiyalar satışa buraxılmır. Production statusları əl ilə dəyişdirilməyib.

## 3. Düzəldilmiş təhlükəsizlik və API problemləri

- Login email üçün obyekt qəbul edib Prisma filtrinə ötürürdü. Real HTTP testi bunun yanlış istifadəçi seçə bildiyini göstərdi. LoginDto indi tip, e-poçt və uzunluq sərhədlərini yoxlayır.
- Zod sxeminin Nest metatype kimi işlənməsi user create/update/password-reset-də 500 verirdi. Body `unknown` kimi qəbul olunur, açıq `safeParse` ilə yoxlanır.
- Şifrə reseti və deaktivləşdirmə tokenVersion artırır. JWT versiyası hər sorğuda yoxlanır; hesab yenidən aktivləşəndə köhnə token bərpa edilmir.
- Yeni/reset şifrələri 12–128 simvol tələb edir. Argon2 saxlanıb; mövcud şifrələr dəyişdirilməyib.
- Namizədin başqa filialda qeydiyyatı vasitəsilə bilet sızması bağlanıb. Siyahı, detal və ödəniş satış filialına görə yoxlanır.
- Filial rəhbərinə çoxfiliallı işçinin digər filial təyinatları göstərilmir.
- Rol, filial və status dəyişiklikləri ortaq transaction lock ilə qorunur. Son aktiv SUPER_ADMIN qoruması saxlanıb.
- QR admission və audit eyni transaction-dadır. Audit uğursuz olarsa USED vəziyyəti rollback edilir.
- Health endpoint anonim cavabda daxili DB xəta mətnini açıqlamır.
- İmtahan, filial və sual mutasiyalarına transaction daxilində audit əlavə edilib.
- Docker build context bütün səviyyələrdə `.env` və `.env.*` fayllarını istisna edir.

## 4. Tamamlanan funksiyalar

### İdarəetmə

İstifadəçinin rol/filial redaktəsi API-də saxlanır. Orphan redaktə komponenti dashboard-a qoşulub; hesab deaktivləşdirməsi mümkündür. Ad/e-poçt dəyişərkən mövcud çoxsaylı rollar saxlanır. Passiv filiallar mərkəzi idarəetmədə görünür və aktivləşdirilir.

Əlaqəli məlumatı olmayan boş DRAFT silinə bilir; digər imtahanlar arxivləşdirilir. Sessiya sayı `take: 1` ilə səhv hesablanmır; tutum ACTIVE və USED biletləri nəzərə alır. Dashboard-un saxta “modul hazırlanır” sayğacları real API məlumatı ilə əvəz edilib. Tənzimləmələrdə hesab, filial və real DB bağlantısı göstərilir; secret redaktəsi yaradılmayıb.

### Satış və hesabat

Kassa CASH, CARD/POS və BANK_TRANSFER qeydini göndərir; təsdiq ödəniş növünü CASH ilə əvəz etmir. Keçmiş sessiyaya satış rədd edilir. Server qiyməti, DB tutum trigger-i və namizəd/sessiya üçün partial unique index qorunur.

Ödənilmiş, istifadə edilməmiş biletin manual refund-u mərkəzi administrator və aid filial rəhbəri üçün əlavə edilib. Təkrar refund rədd edilir; CANCELLED/REFUNDED və audit eyni transaction-dadır. Bu, əməkdaşın pulu geri verdiyini qeyd edir; bank əməliyyatı deyil.

Real filial/satıcı/ödəniş/status hesabatı, Bakı tarixi filtri, Excel və brauzerdən çap/PDF əlavə edilib. Frontend download allowlist-i satış Excel ünvanı ilə uyğunlaşdırılıb.

Şəxsi online qəbzdə namizəd nömrəsi göstərilir. PUB- nömrəsi 68 simvol olduğundan nəticə lookup limiti düzəldilib. Açıq QR yoxlamasına şəxsi namizəd nömrəsi əlavə edilməyib.

### Sual bankı, OMR və nəticə

Sual forması examId və düzgün rəqəm tiplərini göndərir. Cavab indeksi variant sərhədindən kənara çıxa bilmir. Fənn, mövzu, HTTPS şəkil URL-si, səhifələmə və filtrlər əlavə edilib. Şəkil dəstəyi URL əsaslıdır; fayl upload servisi deyil.

Uyğun variant saylı aktiv suallar arasından təkrarsız təsadüfi seçim cavab açarına bağlanıb. Açar mövcud immutable snapshot mexanizmini saxlayır. Nəticədə faiz üzrə competition rank, imtahan xülasəsində orta faiz göstərilir. Ləğv edilmiş biletlər reytinq/orta baldan çıxarılır. OMR operatorunun xülasəsi öz yükləmələri və icazəli filiallarla məhdudlaşdırılır.

## 5. Database və miqrasiyalar

## 7. Docker və canlı sistem

Yalnız read-only metadata yoxlanıb. Mövcud layihə `hilalbiletsayt`-dır; API, PostgreSQL, web, worker, RustFS və Redis var. PostgreSQL image adı `postgres:16-alpine`, volume `hilalbiletsayt_postgres_data`; RustFS volume `hilalbiletsayt_rustfs_data`.

API və worker-də mount görünməyib. Köhnə OMR fayllarının yeri müəyyənləşdirilmədən konteynerlər yenidən yaradılmamalıdır. Repository Compose default-u `hilal`-dır; köhnə stack ilə qarışdırmaq olmaz. Yeni kod OMR üçün persistent lokal volume istifadə edir. Redis tətbiqdə istifadə edilmir; RustFS üçün yeni kodda inteqrasiya yoxdur.

API Dockerfile OpenSSL və Prisma generate edir. API/web/worker non-root işləyir. Yeni Docker image-ləri bu auditdə build/deploy edilməyib.

## 8. Hazır olmayan inteqrasiyalar və məhdudiyyətlər

- Online gateway yoxdur: provayder, sandbox, webhook imzası, idempotency və reconciliation inteqrasiyası tələb olunur. Tək API açarı kifayət deyil.
- SMTP/SMS çatdırılması yoxdur. Parol reseti administrator axınıdır; email göndərilmiş kimi saxta cavab verilmir.
- Fiziki printer/skaner, kamera və real cavab vərəqlərinin kalibrasiyası yoxdur. Fixture və worker/PDF sınağı cihaz sertifikasiyası deyil.
- Gözləyən online nağd sifarişlər avtomatik expire olmur; yer ləğvədək tutulur. Bu əməliyyat qaydası qəbul edilməli və ya ayrıca expiry işi görülməlidir.
- Bağlanmış kassa günü dəyişməzdir. Sonrakı refund üçün ayrıca adjustment yoxdur; trigger belə dəyişməni bloklayır.
- Mövcud OMR ixracında 5000 sətir, nəticə xülasəsində 200 imtahan limiti var; böyük həcm üçün əlavə iş lazımdır.
- Xarici pentest, production backup/restore və yeni image-lərlə staging tamamlanmayıb.
